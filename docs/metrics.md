# Metrics (R9 daily metrics, R10 mailbox alert)

Evidence for judging criterion 3 ("works every time") and 5 ("real use outside the event").
Targets: **≥99% of chat messages answered, p95 reply latency <15 s.**

## How it works
- **VPS** `deploy/collect_logs.sh`, cron every 5 min (`/etc/cron.d/agent-doctor-collect`) and once
  before each deploy: copies `REQ` lines (hashed ids, no message text), mailbox poll errors (status
  code only), hourly heartbeats and starts from Docker logs into `/opt/agent-doctor/logs/events.log`.
  Docker rotation and container re-creation can't drop them after that.
- **Local** `scripts/metrics.py --pull` (sandbox off, SSH): copies that file to `data/events.log`
  (gitignored) and rewrites the generated block below. Run once a day. Exit code 2 = outage alert
  in the newest day.
- Install the collector without an agent deploy: `deploy/install_collector.sh` (sandbox off).
- Guard budget before a Testing batch: `scripts/metrics.py --pull --sessions` prints each chat session's
  answered replies since the last restart (last hour / 24 h), what's left before the guard's 20/h or
  50/24 h cap silences it for 24 h, and dropped/rate-limited counts. Printed only, not written here.

## Definitions
- **Chat message**: any Chat Protocol request except session markers. **Answered**: not dropped by
  the guard. **Errors**: `api_down`, `timeout`, `fallback`, `prehire_error` (user got "try again").
- **Pre-Hire protocol calls**: `AgentDoctorPreHire` requests from other agents (not chat).
- **Outside use**: senders in `scripts/metrics_exclude.json` removed (user's own ASI:One hash; add
  the Testing evaluator, P6 demo client, dev agent when seen). A sender hash is not a person: ASI:One
  may relay many users under one sender, so sessions are counted too. Watch "excluded sessions": if
  it grows past the user's own chats, the user's hash is a shared relay and the exclusion is wrong.
- **Mailbox error streak (R10)**: mailbox poll errors with no quiet gap over 330 s. uagents 0.26.1
  polls every 1 s and logs only failed polls (successful polls leave no line); aiohttp's default 300 s
  timeout bounds the time between two failed polls. A streak ≥30 min = **ALERT**. A single successful
  poll inside a streak is invisible. Alert only: no auto-restart (503s come from Agentverse).
- **Heartbeat**: uagents logs "Registration on Almanac API successful" every 3600 s while running.
  A gap over 90 min = **ALERT** (agent down or registration failing).

## Caveats
- Data starts when the collector first ran. Lines from containers replaced before that are gone.
- Collection lags up to 5 min.
- Collector installed 2026-11-02 22:03 UTC (`deploy/install_collector.sh`, no agent restart).
  First run back-filled the live container's logs from its start (10:03 UTC).
